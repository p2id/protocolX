# Community schedule proposals

This folder is the **canonical collection of maintainer-approved public schedules**. Do not put unreviewed submissions here.

## Required publication path

**Propose → Review → Approve → Publish**

1. **Propose:** submit a GitHub issue or pull request with an anonymized, editable Markdown schedule. The interactive generator's “Prepare GitHub contribution” button creates only a draft; a person must review and submit it.
2. **Review:** a maintainer checks leisure-only scope; the necessity framing; exactly two session types; real-world default; self-sufficiency and low-cost assumptions; accessibility and safety; a reason for every digital session; digital-cap arithmetic; the three-part session review; the required weekly review; privacy; portability; and consistency with the core protocol.
3. **Approve:** a maintainer explicitly approves the proposal or requests changes. Community feedback alone is not approval.
4. **Publish:** only a maintainer-approved change is merged into this folder. No tool or workflow may auto-publish generated schedules here.

## Proposal format

Use the [portable schedule prompt and template](../daily-and-weekly-leisure-schedule.md). Give the file a descriptive, non-branded name such as `quiet-low-energy-week.md`. Include the intended audience and adaptation notes only if they are useful and non-identifying.

Before submitting, remove names, precise locations, contact details, sensitive information, and personal post-session reflections. Keep generated activity content free of brands and named entities. Do not imply one schedule fits everyone.

## Canonical collection

Only maintainer-reviewed and approved schedules belong here. The folder may remain empty until a suitable proposal passes review.
